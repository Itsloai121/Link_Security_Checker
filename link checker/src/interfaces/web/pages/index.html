You cannot judge a link by looking at it.

Every trick on this page makes a dangerous link look ordinary. They work because people check the part of an address that is easiest to fake. Unmask checks all of it, including the parts you cannot see.

paypa1.com

A number pretending to be a letter. Swapped characters, extra words and small misspellings imitate a brand you trust.

https://trusted.com@evil-site.example

Everything before the @ is decoy. Browsers ignore it, but your eyes read it first.

bit.ly/3xYzAbc

A short link with a hidden destination. The real address only appears after one or more redirects.

xn--pypal-4ve.com

Letters from another alphabet. A Cyrillic “а” looks exactly like a Latin “a”, so a fake domain reads as the real one.

trusted.com/go?url=evil.example

A trusted site that bounces you elsewhere. The link starts somewhere reputable and lands somewhere that is not.

the page itself

A page that behaves differently when inspected. Some phishing pages show scanners one thing and visitors another.

Three steps, no clicking.

  1. Paste the link

    Copy it from the message instead of clicking it. If you know the text it displayed, add that too so we can compare label and destination.

  2. We follow it for you

    Our server walks the redirects, reads the page, and looks up the domain, certificate and network. The link is never opened in your browser.

  3. Read the report

    You get a verdict, a risk score and all 20 tests in plain language, with the evidence behind each one.

What Unmask cannot promise

  • No tool can prove a link is safe. “No threats found” means these 20 tests found nothing, not that nothing exists.
  • Brand-new attacks may not be on any blocklist yet. That is why the other tests inspect the link, the journey and the page itself.
  • Pages are read, not run. Content that only appears after JavaScript executes can stay hidden, and the report says so.
  • If a test cannot run, it is marked “Not verified”, never “Clear”.
